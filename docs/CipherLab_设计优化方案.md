# CipherLab 视觉设计优化方案

> 本文档面向执行代码生成的大模型（ArkTS/ArkUI），可直接作为实现依据。所有数值均可直接使用，不需要二次解释。

---

## 0. 设计定位（先读这一段再动手）

**主题**：CipherLab 的 10 个"算法"页面本身是一条历史时间线——从凯撒（公元前）到 Enigma（二战）再到 RSA/DH（现代公钥）。这条时间线是现成的、内容自带的结构信息，不需要额外发明叙事。

**设计概念**："破译者的工作台"（The Codebreaker's Desk）——深墨色的工作台背景 + 方格纸计算区（矩阵、模运算等需要"演算"的页面）+ 双色语义系统：**加密态用琥珀/黄铜色，解密态用青色**，贯穿全app，让用户不看文字也能分辨"这是密文"还是"这是明文"。

**要避免的三种AI默认风格**（详见下方 token，本方案已刻意避开）：
1. 暖米白 + 衬线大字 + 陶土色（terracotta ~#D97757）
2. 纯黑背景 + 单一荧光绿/朱红点缀
3. 报纸式零圆角细线网格

**签名元素（全app唯一的记忆点）**：翻页时刻表式的"字符翻转"动画（split-flap，类似老式车站翻页牌）——明文字符逐个翻转变成密文字符。这个动效不是装饰，它就是产品的核心卖点（"逐步动画演示加密原理"），复用在所有算法页面的结果展示区。

## 1. 设计 Token（颜色）

### 1.1 基础色板

| Token | 值 | 用途 |
|---|---|---|
| `bg-base` | `#12161D` | 页面背景（墨蓝黑，非纯黑）|
| `bg-surface` | `#1B212B` | 卡片背景 |
| `bg-surface-raised` | `#242B37` | 悬浮/激活卡片 |
| `border-hairline` | `#2E3644` | 分割线、卡片描边 |
| `text-primary` | `#EDEFF3` | 主文本 |
| `text-secondary` | `#9AA3B2` | 次要文本/说明 |
| `text-tertiary` | `#5C6572` | 禁用/占位文本 |

### 1.2 语义双色系统（核心，贯穿全app）

| Token | 值 | 语义 |
|---|---|---|
| `accent-encrypted` | `#D6A24C`（琥珀/黄铜）| 密文、"加密"按钮、锁定态图标 |
| `accent-decrypted` | `#3FBFC4`（青色）| 明文、"解密"按钮、解锁态图标 |
| `accent-danger` | `#E2645A` | 错误、无效密钥 |
| `accent-success` | `#6FCF7C` | 挑战答对、校验通过 |

**执行规则**：任何界面元素只要在表达"这是密文/已加密/锁定"就用 `accent-encrypted`；表达"这是明文/已解密/可读"就用 `accent-decrypted`。不要混用，不要额外发明第三种"中性强调色"。

### 1.3 十种算法色——按时间线渐变生成，不要手动挑色

10个算法页按 `ComparePage` 里的历史顺序，从暖色（古典）过渡到冷色（现代），用统一的 HSL 曲线生成，保证是"一个家族"而不是随机撞色：

```
色相(H)：从 30°（凯撒，古典/羊皮纸感）线性过渡到 250°（DH/哈希，现代/数字感）
饱和度(S)：固定 55%
明度(L)：固定 58%（保证在深色背景上可读且不刺眼）

具体分配（10个点，等距）：
Caesar      H=30   → #C98A4A
Vigenere    H=52   → #C6A046
XOR         H=74   → #A8B347   （注：若按你实际页面顺序不同，按顺序重新等分即可）
Hill        H=96   → #7CBB55
OTP         H=140  → #5CBB7F
Base64      H=164  → #4FBBA3
Enigma      H=188  → #4CADBE
RSA         H=210  → #4C93C7
DH          H=232  → #5A7FCC
Hash        H=250  → #6E72C9
```

> 执行说明：以上仅为算法色示例分配，实际请按 `ComparePage` 展示顺序重新等分 H 值（30→250，10等分），S/L 保持不变，用公式统一生成，不要单独调色，避免出现色彩关系混乱的观感。

### 1.4 工具色（6种，用于"自定义/分析/学习" Tab）

沿用现有语义色规则，但明度略降（L=48%），与算法色区分开：分析类偏冷灰蓝，学习类偏中性紫灰，自定义类偏中性棕灰。不需要单独强记忆色，因为这些是"功能性"页面而非"内容性"页面。

## 2. Typography

- **UI 主字体**：`HarmonyOS Sans`（系统默认，覆盖 Thin~Black 全字重）用于所有正文、按钮、导航标题。
- **密文/数据展示专用字体**：打包一款等宽字体（推荐 `JetBrains Mono` 或 `Space Mono`，作为 rawfile 字体资源引入），**只用于**：密文/明文字符串展示、矩阵数值、二进制/十六进制展示、频率分析数字。这是全app唯一额外引入的字体，克制使用，不要在标题/正文里用等宽字体。
- **字号阶梯**（vp）：34（页面大标题，仅首页Tab用）/ 24（页面二级标题）/ 17（正文）/ 15（次要说明）/ 13（标签/eyebrow，全大写+字间距1.5vp）。
- **等宽字体字号**：密文展示区用 20~28vp，行高 1.6，保证逐字符动画时的可读性。

## 3. 布局与组件

### 3.1 方格纸计算区（仅用于真正涉及"演算"的页面）

Hill（矩阵）、DH（模幂运算）、RSA（大数运算）、频率分析、Kasiski 页面的核心演算区域，背景叠加 2% 透明度的 8vp 间距网格线（`border-hairline` 色，透明度 0.06）。**其余页面不加**，避免网格纸滥用成为新的"模板感"。

### 3.2 PageNavBar 重设计

- 左：返回箭头（保持功能不变）
- 中：标题用等宽字体 + 全大写 + 字间距，类似档案戳记的观感（不需要真的做印章特效，字体处理即可）
- 右：不再是纯文本，改为一个小徽标（pill 形状，`bg-surface-raised` 底 + 12vp 文字），显示该算法的"分类标签"，如 `古典密码` / `公钥密码` / `哈希函数`，颜色取该页面分配到的算法色

### 3.3 StepButtonBar 重设计

改为"胶带式"步骤条：一条 2vp 横线贯穿，每一步是线上的一个圆点（8vp），当前步骤的圆点放大到 12vp 并填充当前模式对应的语义色（加密流程用 `accent-encrypted`，解密流程用 `accent-decrypted`）。不要用纯数字 Tab 式步骤条，圆点+连线更贴近"信号路径"的隐喻，且和 Enigma 页面的"转子信号追踪"视觉语言天然一致。

### 3.4 PrincipleCard 重设计

- 左侧 4vp 竖条，颜色取该算法分配色
- 顶部 eyebrow 文字 "原理"（13vp，全大写字间距，`text-tertiary`）
- 背景可选叠加方格纸纹理（仅数学类算法启用，见3.1规则）
- 圆角 12vp，不用 0 圆角（避免落入"报纸风"默认套路）

### 3.5 SectionHeader

- 仅在内容确实是"有序步骤"时才用数字编号（如 RSA 7步演示、DH 6步演示、加密链自定义）
- 其余分组（如首页Tab内的算法列表）用 eyebrow + 分隔线，不加编号

## 4. 动效（核心卖点，不是装饰）

### 4.1 全局签名动效：字符翻转（split-flap）

明文→密文的每个字符变换，用类似车站翻页时刻表的旋转翻转效果：
- 单字符翻转时长 180ms，`cubic-bezier(0.4, 0, 0.2, 1)`
- 多字符按 40ms 间隔依次触发（从左到右），形成"连锁翻牌"的观感
- 翻转中途色从 `accent-decrypted`（明文态）过渡到 `accent-encrypted`（密文态），解密方向相反
- 复用位置：CaesarPage、VigenerePage、XorPage、OtpPage、Base64Page 的核心结果展示区必须使用同一套翻转组件（建议封装为 `CipherComponents` 里新增的 `FlipCipherText` 组件），这是保证"这是同一个app"的关键统一手段

### 4.2 Enigma 专属：机械转子

- 三个转子用真实的旋转动画（非渐变淡入），转动时用 `cubic-bezier(0.6, 0, 0.4, 1)` 制造"咔哒"式的机械停顿感，而不是匀速旋转
- 信号路径用一条描边动画从输入字母走到输出字母，逐段点亮，而不是瞬间画出整条线

### 4.3 Hill 专属：矩阵演算

矩阵单元格按参与计算的顺序依次高亮脉冲（scale 1→1.06→1，180ms），乘加过程用数字滚动（odometer 效果）而非直接跳变数值

### 4.4 全局规则

- 页面间转场：水平滑动 260ms，不用淡入淡出（淡入淡出是最容易显得"随意"的默认选择）
- 必须适配"减弱动画"系统设置：关闭后所有动效退化为直接跳变，不做渐变过渡

## 5. 深色/浅色模式扩展方案（对应你的待办事项）

当前 `AppColors` 建议改为语义 token 而非写死色值（即上面 1.1/1.2 表格里的 token 名，而不是直接引用十六进制）。浅色模式不是简单反色，而是切换到"纸质档案"变体：

| Token | 深色值（当前）| 浅色值（新增） |
|---|---|---|
| `bg-base` | `#12161D` | `#F2EFE6`（做旧牛皮纸感，不是纯白）|
| `bg-surface` | `#1B212B` | `#FBF9F3` |
| `text-primary` | `#EDEFF3` | `#1F242C` |
| `accent-encrypted` | `#D6A24C` | `#B87F2E`（降低明度以在浅色背景可读）|
| `accent-decrypted` | `#3FBFC4` | `#1D8E92` |

算法色同理，S 保持，L 从 58% 降到 42%（浅底需要更深的色才能保证对比度）。

---

## 6. 执行优先级建议

1. 先落地 1.1/1.2 语义色 token 替换（影响面最大，风险最低）
2. 再做 4.1 的 `FlipCipherText` 统一组件（这是"体验统一感"的关键，比单个页面的美化优先级更高）
3. 再做 PageNavBar / StepButtonBar 组件级重设计
4. 最后做 Enigma/Hill 等单页专属动效精修
5. 深色/浅色 token 化放最后，因为它要求前面的颜色都已经是语义 token 而非硬编码
